The demo sequence

  1. Show the report. Explain that the historical fix is hidden from the investigator.
  2. Show the failure. Play the recorded game actions and point to the actual symptom.
  3. Show the investigation. Reveal the reduced replay, source findings and candidate diff.
  4. Show the evidence. Display the same target state after patching and all five validation gates.
  5. Show the collection. Include failed attempts, timing, model identity and paired negative controls.

Use the recorded data-patch walkthrough for predictable pacing. It shows selected screenshots with real capture times, not live video. A fresh live attempt is optional.

Protect the scope

Prioritize repeatable evidence and one approved candidate before adding more cases or dashboard polish.

  • Defer multiplayer, distributed workers and automatic upstream PR publication.
  • Do not skip upstream assertions to make validation green.
  • Keep future fixes and evaluator metadata out of investigator workspaces.
  • Report curated-case results with explicit denominators. Matched controls are not additional independent bugs.
